# Documentation audit — TopFarms

> Produced 2026-08-25, after the design-system sync. Read-only survey plus a consolidation
> plan. **Nothing has been moved or deleted.** Every number below came from a command, and
> the commands are in §7.

---

## 0. The shape of it

| | |
|---|---|
| Tracked Markdown files | **509** |
| Total lines | **129,626** |
| Of which `.planning/` | **424 files · 111,975 lines** (86%) |
| Of which belongs to **closed** work | **~361 files** — 146 in shut milestones, 179 in shipped phases, 13 design-gate, 11 go-live, 12 misc |
| One-shot "paste this into a session" prompts | **32**, four written this month |
| Documents a session is actually told to read | **~20** |

The repo is not under-documented. It is documented **~25× more than it can keep true**, and
the excess is not inert: four of the five entry-point documents currently disagree about what
state the product is in.

## 1. Six readiness scores, all in live documents

`grep -o "[0-9]\{2\}/100"` across the three files a session is pointed at returns:

| Score | Where | Date |
|---|---|---|
| 62 → **93**/100 | `LAUNCH.md` header | 2026-07-23 |
| **53**/100 | `LAUNCH.md`, in its own ⚠️ SUPERSEDED banner four lines below the 93 | 2026-07-30 |
| **46**/100 ×2 | `LAUNCH.md` body | — |
| **91**/100 | `LAUNCH.md` body | — |
| **72**/100 | `.planning/PRE-LAUNCH-CHECKLIST.md` | 2026-08-21 |

`LAUNCH.md` contradicts itself in its own first ten lines. A reader who stops at the header
believes 93; the truth, per the most recent honest re-walk, is **72 with an engineering
ceiling of ~81**. That figure exists in exactly one file and it is not the one called
`LAUNCH.md`.

**This is the single most expensive documentation defect in the repo.** It is also why
session memory carries a note titled "Score is 72, not 80" — a memory entry is doing the job
a document should be doing.

## 2. `.planning/STATE.md` — 11,085 words, one of which is a sentence

The GSD state file's `stopped_at` field is **1,340 words / 9,765 characters inside a single
quoted YAML string**. It is a wall of run-on prose covering Phase 28, the leads-triage
stream, the harvest cron, a Vault secret rotation, an MCP read-only incident, and the
2026-07-02 domain go-live — with sub-clauses correcting earlier sub-clauses in the same
field.

It was last touched **2026-07-02**. It is **eight weeks stale**, and `.planning/NOW.md` opens
by saying so:

> "Written 2026-08-06 because state had spread across `STATE.md` (5 weeks stale), four
> off-roadmap stream directories, session memory, and 66 git branches."

So `NOW.md` exists **because** `STATE.md` failed, and `STATE.md` is still sitting there
looking authoritative. Two files claiming to be "where the work is", one of them wrong, and
the wrong one has the more official-sounding name.

## 3. The entry-point problem

`CLAUDE.md` names 12 documents. `NOW.md` names 20 more. Between them a session is pointed at
**~30 files before it has read a line of code**, and they are not consistent with each other:

| Document | Claims | Last true |
|---|---|---|
| `SPEC.md` (1,080 lines, repo root) | "Status: Final — ready for `/gsd:new-project`" | **2026-03-17** — five months ago, pre-launch, pre-v2 brand |
| `.planning/PROJECT.md` | describes "full SPEC v3.0 compliant UI" | 2026-06-22 |
| `.planning/ROADMAP.md` (509 lines) | milestone plan through v2.x | 2026-06-29 |
| `.planning/STATE.md` | milestone v2.2, `status: leads-triage-complete` | 2026-07-02 |
| `LAUNCH.md` | 93/100, superseded by itself | 2026-08-11 |
| `.planning/NOW.md` | 72/100, supply-first, launch is a market problem | **2026-08-25 — the only current one** |

`SPEC.md` and `ROADMAP.md` both still describe Fraunces and DM Sans, a brand retired in
**June**. They are harmless as history and dangerous as instructions, and nothing in them
says which they are.

## 4. Thirty-two one-shot prompts, filed as if they were documentation

Files written to be pasted into a session once and then discarded, still tracked:

- `.planning/`: `NEXT-SESSION-PROMPT` · `NEXT-BATCH-PROMPT` · `NEXT-SLICE-PROMPT` ·
  `SESSION-RESTART` · `.continue-here` · `UPLIFT-95-PROMPT` · `D4-AND-SEARCHHERO-PROMPT` ·
  `DESIGN-SYNC-PROMPT` · 3 × `SESSION-HANDOFF-2026-05-0x` · `go-live/NEXT-SESSION`
- `docs/`: **15 more** — `PHASE-0` through `PHASE-5-STAGE-0`, `ADMIN-PORTAL-V2`,
  `CI-GATE-AND-ANALYTICS`, `LAUNCH-READINESS`, `LEADS-PIPELINE-V2`, `PRE-LAUNCH-AUDIT`,
  4 × `SESSION-HANDOFF-2026-07-xx`

Four were written **this month**, including two by me. They read like current instructions
because they are phrased as instructions, and nothing distinguishes a prompt that was
consumed in July from one written yesterday.

`docs/` is meant to be the durable reference shelf. **Fifteen of its ~30 root files are spent
prompts.**

## 5. What is actually healthy

Worth saying, because the fix is not "burn it down":

- **`docs/_canonical/`** — five files, clear name, now correct after today's pass. The pattern
  works; almost nothing uses it.
- **`docs/_superseded/2026-08-25/`** and **`_archive/2026-06-20/`** — dated supersession
  folders, exactly right. Two of them exist and they hold seven files between them.
- **`.planning/NOW.md`** — genuinely current, honest about its own authority ("if this file
  and a stream doc disagree, the stream doc wins and this file is out of date — fix it").
- **`CLAUDE.md`** — operational, tested against reality, and every rule in it traces to an
  incident. It is the best document in the repo.
- **`docs/design/contrast.md`** — generated by `scripts/contrast.mjs`, so it cannot go stale
  without the gate going red. **This is the only self-verifying document here**, and it is the
  model for the rest.

## 6. The consolidation plan

Ordered by confusion removed per minute. Nothing here is destructive: everything moves to a
dated `_superseded/` folder and stays in git history regardless.

### A — Kill the contradictions (30 min, do first)

1. **`LAUNCH.md`** → `docs/_superseded/2026-08-25/`. It contradicts itself in its own header
   and the live number lives in `PRE-LAUNCH-CHECKLIST.md`. Leave a three-line stub at the
   root pointing there.
2. **`.planning/STATE.md`** → `_superseded/`. `NOW.md` was written to replace it and says so.
   Eight weeks stale, and the format actively resists being kept true.
3. **One score, one place.** `PRE-LAUNCH-CHECKLIST.md` owns readiness: **72/100, ceiling ~81**.
   Every other file cites it rather than restating it. A number repeated in four places is a
   number wrong in three.
4. **`SPEC.md`, `.planning/ROADMAP.md`, `.planning/PROJECT.md`** get a one-line banner —
   *"Historical. Written for v1.0/v2.x planning; superseded by `.planning/NOW.md`."* Keep
   them; they are decision records. Just stop them reading as instructions.

### B — Separate prompts from documentation (20 min)

5. `mkdir .planning/prompts/_spent/` and move all 32 there, keeping only prompts for work not
   yet started at the top level. A prompt is a **message**, not a reference; the folder name
   should say so.
6. `docs/` root keeps only durable reference: `DESIGN.md`, `PRODUCT.md`, `SEEKER-INSIGHTS.md`,
   `TEST-BACKLOG.md`, `DOC-AUDIT` (this file), plus `_canonical/`, `design/`, `immigration/`,
   `evidence/`, `uat/`. Everything else to `_superseded/2026-08-25/`.

### C — Retire closed work (15 min)

7. `.planning/milestones/` (146) and `.planning/phases/` (179) are records of **shipped**
   work. Move to `.planning/_archive/` wholesale. They stay searchable, they stop appearing in
   every glob, and `.planning/` drops from 424 files to **~60**.
8. Same for the completed streams: `design-gate/`, `admin-design-gate/`, `go-live/`,
   `v2-migration/`, `snapshots/`.

### D — Make it stay fixed (the only part that matters long-term)

9. **One map, at `docs/DOCUMENTATION.md`**: what is canon, what is current state, what is
   history, and the rule that a document not listed there is history. `CLAUDE.md` points at
   it and nothing else.
10. **Stop summarising canon.** Today's pass found the marketing brand summary wrong on
    *every line*, and three other docs asserting retired values. A summary of a canon is a
    copy of a canon, and copies rot. Where a summary is genuinely needed, it says out loud
    that it is a pointer, not a source.
11. **Prefer generated over written.** `contrast.md` is regenerated by its own gate and cannot
    drift. The token table, the retired list and the readiness checklist could all work the
    same way. Every document that a gate does not check is a document that will be wrong.

### Result

| | Now | After |
|---|---|---|
| Files in `.planning/` | 424 | ~60 |
| Root `.md` | 6 | 2 (`CLAUDE.md`, `README`-style stub) |
| `docs/` root | ~30 | ~6 |
| Documents claiming current state | 6, disagreeing | 2 (`NOW.md`, `PRE-LAUNCH-CHECKLIST.md`) |
| Readiness scores in live docs | 6 | 1 |

**Total ~65 minutes**, all of it moves and banners, none of it deletion.

## 7. Reproducing this

```bash
# §0 counts
git ls-files '*.md' | wc -l
git ls-files '*.md' | xargs wc -l | tail -1
git ls-files '.planning/*' | grep -c '\.md$'

# §1 conflicting scores
grep -rhoE "[0-9]{2}/100" LAUNCH.md .planning/PRE-LAUNCH-CHECKLIST.md .planning/NOW.md \
  | sort | uniq -c

# §2 the stopped_at field
python3 -c "import re;s=open('.planning/STATE.md').read();\
m=re.search(r'stopped_at:\s*\"(.*?)\"\n',s,re.S);print(len(m.group(1).split()),'words')"

# §3 staleness of the entry points
for f in SPEC.md .planning/PROJECT.md .planning/ROADMAP.md .planning/STATE.md \
         LAUNCH.md .planning/NOW.md; do
  echo "$(git log -1 --format=%ad --date=short -- $f)  $f"; done | sort

# §4 one-shot prompts
git ls-files '*.md' | grep -iE "PROMPT|NEXT-|SESSION|CONTINUE|RESTART|HANDOFF"

# docs still asserting a retired design value (should be zero outside _superseded)
git ls-files '*.md' | grep -vE "^(_archive|docs/_superseded)/" | while read f; do
  h=$(grep -oiE "#8CC63F|#F2EDE1|#0F3D22|#141812|Archivo|Fraunces|DM Sans" "$f" | sort -u | tr '\n' ' ')
  [ -n "$h" ] && echo "$f  $h"; done
```
